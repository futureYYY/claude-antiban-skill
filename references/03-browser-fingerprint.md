# 阶段 5：AdsPower 指纹浏览器

## 为什么要它

出口 IP 已经在美国了，但浏览器还会泄露：时区、语言、WebRTC 内网 IP、Canvas / WebGL、字体列表。

改系统时区能解决时区问题，但会影响日常使用。指纹浏览器把这些隔离在单个环境里，本机时钟不用动。

### 时区：别信「基于 IP」的自动判断

实测踩过：时区设成「基于 IP」，检测页报

```
系统时区  America/New_York (UTC-05:00)
IP 时区   America/Los_Angeles (UTC-08:00)   ← 差 3 小时，直接暴露不一致
```

**根因**：AdsPower 的「基于 IP」读的是它自己的 IP 库。这个库对某些美国 IP 只识别到国家，时区就按**美国东部（New_York）兜底**；而检测站点的库知道具体城市，于是两边对不上。不是你的设置写错了，是它的库精度不够。

**做法**：既然出口是固定 IP，就别让它猜——

| 步骤 | 操作 |
|---|---|
| 1 | 时区选 **自定义** |
| 2 | 下拉里选 **`GMT-08:00 America/Los_Angeles`** |
| 3 | 保存后**彻底关闭环境再重开**（SunBrowser 会缓存，不重开不生效） |

**-8 区有好几个同名偏移，只有第一个能用**：

| 选项 | 结果 |
|---|---|
| `America/Los_Angeles` | ✅ 与 IP 字面一致 |
| `America/Tijuana` / `America/Vancouver` | ❌ 偏移相同但 IANA 名不同，检测页会显示成这些 |
| `Etc/GMT+8` / `PST8PDT` | ❌ 一看就不是真实用户 |

检测页比的是 **IANA 时区名**，不是 UTC 偏移量。

**地理位置同理**：可以继续用「基于 IP」；如果要改「自定义」，**必须把纬度和经度填上**（西雅图约 `47.6062, -122.3321`，精度 1000）。只切到自定义却不填，等于让浏览器「无定位」，比不改更假。

**验收**：BrowserScan 里「IP 时区」和「系统时区」两行**字面完全一致**才算过。

## 验收

开环境 → BrowserScan 看**真实性 100%**；再开 `browserleaks.com/webrtc`，应显示 `No Leak`，公网 IP = 服务器 IP。

## 两个坑

1. **媒体设备噪音会影响活体核验。** AdsPower 改写了摄像头 / 麦克风指纹，要调摄像头的流程可能拿到异常设备。
   - **谷歌注册的自拍验证**：自己正常做就行，同一轮最多试两次；超过两次就停，隔满 24 小时再试（越试风控等级越高）。
   - **Persona 的 KYC**：是另一条独立流程，别和注册验证混在一起做。后续如果弹出**门户 KYC**，也应在同一个指纹环境里完成 —— 换环境去做等于自曝。

2. **两个号共用一个环境 = 同一个指纹。** 我这两个号确实跑在同一个环境里，目前没事；但这是账号关联度最高的一环，新增第三个号建议开独立环境，别继续复用。
